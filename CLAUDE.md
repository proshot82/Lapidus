# «Лапидус. Ни капли» — правила для Claude Code

## Кто и как
- Автор — Lao. Отвечай по-русски: сначала ответ, коротко, без воды и без общих предложений в конце.
- Lao — «не разработчик» и часто работает с телефона. Всё, что ему нужно сделать руками (GitHub, настройки,
  установка), — пошагово, ничего не предполагая. Итоги сессии — кратко, без длинных логов.

## Жёсткое правило про решения
- Решения уровней (порядок ходов, кадры, пошаговые описания прохождения) НИКОГДА не пишутся в текст ответа,
  в описание PR, в сообщения коммитов и в заметки для Lao.
- Можно: вывод инструментов (запуски скриптов), puzzles/solutions.json, WALKTHROUGH_SPOILERS.md.
- В отчётах — только метрики и механизмы ловушек общими словами, без порядка ходов.

## Планка качества (требования Lao)
- 10 уровней: первый уже трудный, последний — безумный; ориентир — Jelly no Puzzle и Snakebird.
- Уровни не проходятся наобум, тычками (планка Jelly no Puzzle).
- В каждом уровне «ага», формулируемое одной фразой; уровень кажется нерешаемым за счёт красоты, а не нагромождения
  новых элементов; после решения — «как можно было до такого додуматься».
- Уровни строятся руками от ложного плана; солвер — только проверка. Ворота и их пороги — в HANDOFF.md.
- Юмор, сантехника, канонический Лапидус (лысеющий усатый брюнет). Арт делает Claude (SVG → PNG).
- В сеть выкладывать только готовую версию (10 уровней со звуком). Промежуточные сборки наружу не публиковать.

## Источники истины
- docs/DESIGN.md — дизайн-документ (экспорт ревизии 18 из Claude Doc, 27.09.2026). Дальше правки вносятся сюда.
- HANDOFF.md — план, ворота, состояние уровней. BUILDLOG.md — журнал сборки.
- build/l6b/NOTES.md — итоги поиска нового ядра кв. 6 (26–27.09) и открытый вопрос к Lao.

## Окружение и команды
- Программы (LÖVE 11.5, LuaJIT, rsvg, ImageMagick, ffmpeg, xvfb, zip): если `love` или `luajit` не находятся —
  `bash tools/setup_sandbox.sh` (он же ставит шрифты игры в систему — без них art/*.py откажется рисовать). Текст для поля Setup script облачного окружения — tools/cloud_setup.sh.
- Тесты: `luajit tests/test_rules.lua && luajit tests/test_solver.lua`.
- Отчёты: `luajit solver/run_all.lua 1 2 3 4 5 6` — ВСЕГДА со всеми номерами квартир (перезаписывает отчёты целиком);
  разбор: `luajit tools/review.lua 1 2 3 4 5 6`.
- Автопрохождение: `ALSOFT_DRIVERS=null xvfb-run -a -s "-screen 0 1920x1080x24" love . --autoplay 1 --level N | grep AUTOPLAY`.
- Кандидаты кв. 6: `luajit build/l6b/check.lua build/l6b/<имя>.lua` (все ворота разом; аргумент `frames` печатает кадры —
  только в выводе инструмента), `fate.lua` (куда уходит умная обезьяна), `census.lua`, `traps.lua`;
  генератор раскладок — `python3 build/l6b/mk.py`.
- Долгие прогоны: результаты сразу писать в файлы и коммитить — после простоя облачная машина пересоздаётся,
  фоновые процессы не восстанавливаются.
- Упаковка (позже): скачивание релизов с чужих GitHub-репозиториев (vendor/: сборки LÖVE, apktool) из облака может
  блокироваться прокси GitHub — тогда положить нужные файлы в репозиторий.
